## 기본 원칙

- 릴리스 빌드로만 데모합니다: 태그된 커밋에서 만든 서명된 설치 파일이며, 개발 환경은 쓰지 않습니다. 이 빌드는 아직
  없습니다 (코드 서명 인증서, 계획 항목 J6). 지금의 서명되지 않은 설치 파일은 우리 PC에서 리허설할 때만 씁니다
  ([install.md](../../install/install.md)).
- NG 보드로 시작해 **Compare**를 엽니다. Settings는 요청받을 때만 보여 줍니다.
- 완성된 기능만 보여 줍니다. 그래서 발표자 테마에서는 Settings와 3D Profile이 숨겨집니다.
- 현장 학습은 최대 2분입니다. AI 모델 v1.0이 이미 학습되어 있어 학습을 기다릴 일은 없습니다.
- 고객 이미지가 있으면 항상 그것을 씁니다. 데모 보드 10장은 우리 도구로 그린 것이라 앱이 어떻게 동작하는지만 보여 주고,
  불량을 얼마나 잘 찾는지는 보여 주지 않습니다. 이 보드의 숫자를 정확도로 말하지 않으며, "99.9 %" 같은 말도 하지
  않습니다. 모든 주장에는 건수를 붙입니다 (고객 보드 기준으로 "NG 샘플 14장 중 14장 검출, OK 샘플 60장 중 1장을 NG로
  판정").
- 모든 데모는 고객이 가져가는 보고서로 끝냅니다: 결과 CSV와 불량 박스가 그려진 사진을 USB 메모리에 담아 줍니다.

## 데모 전마다

데모 노트북에서 전날이나 현장에서 한 번 리허설하고 줄마다 확인합니다.

- [ ] 릴리스 빌드가 설치되어 있습니다. 버전을 적어 둡니다: 제목 표시줄과 **Settings** 아래 줄에 나옵니다.
- [ ] 데모 작업 공간을 초기화했습니다: 시작 메뉴에서 `AOI PoC Inspector (Demo)`를 실행하고 **Settings**에서
      **Reset Demo**를 누른 뒤 확인합니다. **Home**에서 **Presenter theme**를 켠 상태로 둡니다.
- [ ] Wi-Fi가 꺼져 있습니다. 앱은 네트워크가 필요 없습니다 ([ports.md](../../install/ports.md)).
- [ ] 프로젝터를 1920 × 1080과 1366 × 768에서 확인했습니다: 스크립트의 모든 페이지가 뒷줄에서 읽힙니다. 페이지는
      1920 × 1080 이상의 화면이 필요합니다 (발표자 테마에서 창은 최소 1888 × 907 px). 1366 × 768에는 아직 맞지
      않습니다 (#104). 1366 × 768만 받는 프로젝터라면 녹화본을 틉니다.
- [ ] **Presenter theme**가 켜져 있습니다 (**Settings**에서 **Presenter theme**).
- [ ] Windows 알림이 꺼져 있고 (집중 모드 또는 방해 금지), 다른 앱은 열려 있지 않습니다.
- [ ] 노트북에는 이 고객의 데이터만 있습니다: 다른 고객의 이미지, 보고서, 이름이 앱, 바탕 화면, 최근 파일 어디에도
      없습니다.
- [ ] 5분 스크립트 녹화본이 노트북과 USB 메모리에 있습니다.
- [ ] 고객 보고서용 빈 USB 메모리에 고객 이름을 붙였습니다.
- [ ] 5분 스크립트를 처음부터 끝까지 한 번 돌리고 다시 **Reset Demo**를 했습니다.

## 문제가 생기면

| 상황 | 할 일 |
|---|---|
| 앱이 닫힘 | 시작 메뉴에서 `AOI PoC Inspector (Demo)`를 실행합니다. 30초 안에 데모 작업 공간이 원래 테마로 다시 열립니다. "다시 열겠습니다"라고 말하고 마지막 단계부터 이어 갑니다 |
| 학습이 느림 | 남은 시간이 2분을 넘으면 **Cancel**을 누르고 이미 학습된 AI 모델 v1.0을 씁니다: "같은 보드로 미리 학습한 것입니다". 잃는 것은 없습니다 |
| 판정이 이상해 보임 | **Compare**를 엽니다. 표에 검사마다 값과 임계값이 있고, 그 아래 상자가 이유를 쉬운 말로 설명합니다. 그것으로 설명하고 추측하지 않습니다 |
| 메시지가 나옴 | 소리 내어 읽습니다. 무슨 일이 있었고 무엇을 할지 코드와 함께 적혀 있습니다. 그대로 하고 이어 갑니다 |
| 프로젝터 없음 | 녹화본을 틀고 보고서는 평소처럼 건넵니다 |

## 데모 후

1. 보고서가 담긴 USB 메모리를 건넵니다 (5분 스크립트의 마지막 단계).
2. **Exit presenter theme**를 누르고 **Settings**에서 **Reset Demo**를 눌러 다음 데모를 깨끗하게 시작합니다.
3. 고객이 서면으로 보관에 동의하지 않았다면 노트북에서 고객 이미지를 지우고, 무엇을 얼마 동안 보관하는지 적어 둡니다.
4. 고객의 질문과 다음에 보고 싶어 한 것을 적습니다. Stage 1 시험 계획에 들어갑니다.

## 스크립트를 믿을 수 있는 이유

`tests/test_demo_scripts.py`가 모든 풀 리퀘스트에서 발표자 테마로 5분 스크립트와 15분 스크립트를 실제로 클릭해 보고,
도중에 메시지가 하나라도 나오거나 페이지가 1920 px 화면보다 넓으면 빨간색이 됩니다. 45분 스크립트는 클릭해 보지
않습니다. 이 파일들의 굵은 이름이 실제 버튼이나 페이지인지, 문장이 Charter의
용어를 쓰는지, 각 파일에 한국어 초안이 있는지도 확인합니다. Customers & Launch는 이와 별도로 각 독자 역할의 사람이
릴리스 빌드에서 스크립트를 따라 해 보도록 요구합니다. 릴리스 빌드가 아직 없어서 이것은 아직 하지 못했습니다.
