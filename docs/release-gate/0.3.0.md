# Release gate: build 0.3.0 (release candidate)

The Engineering standard's release gate, box by box, for build 0.3.0, the first build meant for Stage 1 testing at a
customer (plan stage S59, issue #73). Each box says what is done with its evidence, and what is open with who closes
it. **Status: release candidate, gate open.** The candidate is the head of the S59 pull request; after Jay merges it,
its commit is tagged `v0.3.0-rc.1` and CI builds the unsigned installer from the tag (`build.yml`). No box below is
ticked by that build: a release is a signed installer from a tagged commit after two approvals (Engineering,
"Signing"), and boxes 2 to 7 need the reference PC, a customer's data or a native reader. Results on synthetic boards
in this note are a load for the app, never an accuracy.

## Traceability and approvals

- "A requirement with no test, or code with no requirement or bug ID, fails the release gate": the trace gate on
  every pull request (box 1) checks both; the trace matrix is each run's `trace-matrix` artifact.
- "Release builds come only from CI on a tagged commit after two people approve, signed": one person, Jay, approves
  today. The written exception for the second approver (J8) and the signing certificate (J6) are open
  (`docs/security/threat-model.md`, Decisions 5 and 6).
