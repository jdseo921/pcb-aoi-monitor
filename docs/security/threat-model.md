# Threat model (build 0.3.0)

One page per product area, reviewed against STRIDE at every minor release (Engineering standard, "Scans and SBOM",
MUST). This review was written for build 0.3.0 (stage S59), the build for Stage 1 testing, and checked against the
code at its release candidate: each row names what is in place with the file or test that does it, what is a gap
with the stage, issue or open item that closes it, and what needs Jay's decision. Nothing here has been tried on the
reference PC or at a customer site, and results on synthetic boards are a load for the app, never an accuracy. Jay's
merge of this file is the review of record for 0.3.0; the next review is due with 0.4.0. The release-gate note for
0.3.0 is `docs/release-gate/0.3.0.md`. **Status vocabulary:** *In place* (with the file or test), *Gap* (with the
plan), *Decision* (Jay chooses), *n/a* (with the reason).

## The system in one paragraph

A Windows PC on the line runs the app as a standard user, installed for every user of the PC into
`C:\Program Files\AOI PoC Inspector` by an internal, unsigned installer (`installer/aoi.iss`, page 4). Each Windows
user's data lives in one workspace folder (`%USERPROFILE%\AOI_Workspace` by default; `docs/ARCHITECTURE.md`,
"Workspace on disk"): the SQLite database, the JSON-lines log, sample and inspection images, AI models (`.pt` with a
Golden board PNG and an AI model card), frozen dataset manifests and exports; `settings.json` sits in the default
workspace folder (`~/AOI_Workspace`, or `$AOI_WORKSPACE`) even when it points the app at another workspace. The demo
workspace sits beside it (`<workspace>-Demo`), loaded from the bundle the installer ships, and each customer's dataset
store key sits in Windows Credential Manager under the Windows account (ADR 0010). Images come from a folder (a camera
in Stage 2), results stay on the station, and nothing talks to a network: `aoi/` imports no HTTP, socket or subprocess
module, no setting turns on such a feature ("Offline and least privilege", MUST), and a scripted session of the app
makes no network call and holds no socket (`tests/test_offline.py`, REQ-SET-003); Print Sheet… hands a recovery sheet
to the Windows print system, which may send it to a network printer. Operators inspect; Engineers import, label,
freeze, train, tune and export; Admins manage users, settings and dataset stores and delete records and samples. Every
Engineer and Admin write goes through `AppContext` (`aoi/core/services.py`), which checks the role with `@requires`
and appends an audit entry, and so does Save Image… (F9, `export_board_image`, #241), the one role-checked write every
role may make; an Operator's inspection record, an alarm and the start-up retention sweep are written without a role
check or an audit entry, by design (`tests/test_roles_and_audit.py` lists them), and the app's main view loads and
resets the demo workspace through `aoi/core/demo.py`, outside `AppContext` (page 3). Screens never reach the database,
build an engine or write a picture (`tests/test_layers.py`). Every role check is as strong as the user picker: Switch
User lists every user and asks for nothing until sign-in arrives (REQ-USR-002, release 1.0; page 1). **Trust
boundaries:** (1) the person at the keyboard and the role they pick; (2) files brought in from outside: images and
folders on USB or a share, an AI model file dropped into `models/`, and the demo bundle (the install folder's, or the
folder `AOI_DEMO_BUNDLE` names); there is no recipe or AI model import feature; (3) files going out: exports, AI model
deliverables, printed recovery sheets; (4) the workspace folder and the Windows account's Credential Manager, which the
OS protects and the app does not defend against a Windows administrator (ADR 0002, decision 6, accepted by Jay's merge
of PR #14 on 2026-10-08); (5) the build and install chain: GitHub Actions, the lock files, PyInstaller, Inno Setup and
the unsigned installer.

## Page 1: Inspection

**What it does.** The Operator loads images (a folder today, a camera in Stage 2), the engine aligns each board to
the Golden board, scores it, decides OK, WARN or NG with the recipe's thresholds, saves the record with its overlay and
maps, raises an alarm on NG or on a coded refusal, and Compare shows the board beside the Golden board it was judged
against. Logs & Export lists the records, exports them as CSV and overlay pictures, archives old ones and, for an
Admin, deletes them. **Assets:** verdicts and their evidence (inspection rows, checks, overlays, maps), the station's
availability during a shift, customer board images. **Entry points:** image files, the recipe and active AI model
(pages 2 and 3), the Operator view, Logs & Export.

| STRIDE | Threat | Status |
|---|---|---|
| Spoofing | A result is recorded under another Operator's name, or anyone acts as an Engineer or Admin: every user is picked from a list, with no sign-in | **Gap.** Switch User lists every user, Admins included, and asks for nothing (`MainWindow.switch_user` in `aoi/ui/main_window.py`), and a start on a workspace with no board model signs in its first Admin (`start_user`, called with `setting_up` from the same file), so the operator on a result and the user on an audit entry are labels, not identities. ADR 0002 (`docs/adr/0002-local-sign-in.md`), accepted by Jay's merge of PR #14 on 2026-10-08, sets the fix: Operators pick a name, a station setting adds a 4 to 6 digit PIN, and Engineers and Admins sign in with a secret kept only as an Argon2id hash. **Plan:** REQ-USR-002 to REQ-USR-005, MUST at release 1.0 (`docs/requirements/stage1.md`); until then the G1 validation report says that audit entries name a picked user (ADR 0002, Consequences) |
| Tampering | A verdict or its evidence is changed after the fact, in the database or on disk | **In place for the audit trail:** the audit table refuses UPDATE and DELETE by trigger (`aoi/data/migrations/0003_audit.sql`, REQ-LOG-004) and, since #196, an INSERT OR REPLACE or REPLACE INTO that reuses an entry's id or UUID (`0010_audit_no_replace.sql`; the connection turns on `recursive_triggers` in `aoi/data/db.py`, so a REPLACE meets the delete trigger). **Gap for the records:** no trigger protects `inspections`, `defects` or `checks`, the evidence of what decided a verdict; the start-up retention sweep and Archive set the archived flag, Delete Records… deletes rows by design (next row), and `defects` and `checks` rows go with their inspection (`ON DELETE CASCADE`), so only code discipline keeps a verdict row from being changed. **Gap for the disk:** a Windows user with access to the workspace can edit `aoi.sqlite` or an overlay directly, and the installer sets no permissions on the workspace (page 4). **Decision 4:** a trigger that refuses changes to the verdict columns, `checks` and `defects` while letting the archived flag and Delete Records… through, a hash chain over the rows for customer evidence, or both |
| Repudiation | Records are archived or deleted to hide a verdict (Logs & Export, REQ-LOG-003) | **In place:** Archive needs the Engineer role and writes `inspection.archive` with the days and the count, and archived records stay listed with Include archived; Delete Records… needs the Admin role in the service (`delete_inspections` in `aoi/core/services.py`; AOI-USR-001 for an Engineer or an Operator), asks first naming the count with No as the default, takes a typed reason (AOI-LOG-003 without one), deletes the listed records with their checks, defects, overlays and maps, only under `results/`, and writes `inspection.delete` with the records' UUIDs, the filter, the counts and the reason in the same transaction (`tests/test_logs_history.py`, `test_req_log_003_only_an_admin_deletes_records_with_their_evidence_and_an_entry`; `tests/test_roles_and_audit.py`). The start-up retention sweep archives without an entry, by design, and logs `retention.archived`. **Gap:** the delete entry keeps the records' UUIDs, not their verdicts, so a deleted verdict cannot be read back from the trail (Decision 4), and the Admin is a picked name (Spoofing row) |
| Repudiation | "I never inspected that board" | **In place:** every record carries its time (UTC), operator, AI model version and recipe revision with their UUIDs (the revision says whether the AI check ran, #246), the Golden board's file and SHA-256 (migration 0008), the scale it was judged at (migration 0012) and the whole result as JSON with every check's value and threshold (`result_json`, `checks`, migration 0006), so what decided a verdict can be read again as it was (`tests/test_inspection_records.py`, `tests/test_compare_stored.py`); alarms and coded refusals are stored with their codes (REQ-INSP-006, REQ-LOG-005). The record itself is not audited, and only code discipline protects it (Tampering row). **Gap:** weak until the Spoofing row is closed |
| Information disclosure | Customer board images, results or AI models leave the station through an export | **In place:** customer data leaves the workspace only through exports that need a role and write an audit entry naming the destination, relative to the workspace inside it and in full outside it (#196): Save Image… (F9) for every role, one board's picture with its record (`export_board_image`, `export.image`, #241); for an Engineer, Logs & Export's CSV files and overlays (next row), AI Model Test's CSV, report and Validation Report… (`export_csv`, `export_report`), an AI model file with its AI model card (`export_model`) and a dataset version's manifest (Export Manifest…, through `export_csv`); an export whose entry cannot be written removes the files it wrote (#178, `_audit_files` in `aoi/core/services.py`); `tests/test_layers.py` refuses a screen that writes a picture itself (`save_image`, `QImageWriter`, `cv2.imwrite` or a `.save(` with an argument); no image reaches the log and keys that look like secrets are dropped, while exception text and traces are logged verbatim (`aoi/logging_setup.py`, `SECRET_KEYS`). **Decision 8:** the Engineering standard's Security intro says images leave the station only when an Admin exports them, while the code makes exports an Engineer write; sketch decision Q58 (`docs/sketches/logs-history.md`) and #151 give every export to the Admin alone, and #151 is not built. Save Image… stays with every role, audited, because REQ-INSP-005 and the standard's Input rule (both MUST) give F9 to the Operator; whether #151 also takes it from Operators and Engineers is Jay's (#241) |
| Information disclosure | Logs & Export copies records and overlay pictures to a USB stick | **In place:** Export CSV writes the records file and `<name>_checks.csv` together or not at all, no field of them run as a formula (page 3, #113), and Export Image Overlays copies the overlays in the background with Cancel; each asks first, naming the record count, and each entry (`export.csv` per file, `export.overlays`) holds the user, the time, the destination in full, the filter that listed the records and their count (REQ-LOG-002; `tests/test_logs_history.py`, `test_req_log_002_each_export_audits_the_filter_that_listed_its_records`); both need the Engineer role. The demo kit ends every demo with such a report on a USB stick (`docs/demo/README.md`). **Gap:** the app cannot tell a USB stick from another folder, so USB export is not restricted to a role or logged as such ("Hardening extras", SHOULD); two overlays saved before 0.3.0 under one name can meet in one export, the later replacing the earlier (release note known issue, #245). **Plan:** open item for Jay |
| Denial of service | A huge or crafted image stalls or crashes the station mid-shift, or the app slows down over a shift | **In place:** since S23 a file is read by its content, never its name, and refused before a pixel is decoded when it is over the byte or the pixel cap (`AOI-INSP-005`; 200 MB and 50 MP from `settings.json`, the register's proposed values, to confirm), has a side over the decoder's 1,048,576 px (`AOI-INSP-007`), holds no PNG, JPG, BMP or TIFF image (`AOI-INSP-004`), gives no size, is cut short or damaged, or is a JPEG of more than 100 scans or a TIFF whose strips or tiles are too large, more than 4,194,304 or share bytes of the file (`AOI-INSP-006`, #242); the header readers follow the decoders where a file can be read in two ways, so the size measured is the size decoded; within these bounds a crafted file of up to 200 MB can still hold a board some seconds (the costliest found, a 199 MB TIFF, about 10 s on a busy 4-core VM), and the app keeps running (`aoi/core/imaging.py`, `tests/test_image_input.py`). Inspection runs and saves on the pool thread, one board at a time per page, with "Inspecting…" on the banner (`tests/test_no_freeze.py`, `tests/test_run_controls.py`). Since S55 `tools/soak.py` drives the app through its screens, a board every few seconds for hours, and judges slowdown and memory growth against 10 % each; a 72 s run in CI saves every board with growth under 10 % (`tests/test_soak.py`; synthetic boards, a load and never an accuracy). **Gap:** the 8-hour soak on the reference PC is not done (REQ-INSP-011 Partial; `docs/tests/station-checks.md`, check 1; open item for Jay, who runs it or names who does, once the reference PC is named); the Inspection page has no Cancel for a board being decoded, since Stop acts between boards (REQ-SET-021; release note known issue, #242); the Settings page shows no control for the two caps, so an Admin edits `settings.json`, which `Settings.load` checks at start-up (`AOI-SET-008`); listing 100,000 records at once holds the UI thread about 15 s on a 4-core cloud VM (release note known issue, REQ-LOG-001). **Decision 1:** the per-file cap, and the per-import cap of page 2 |
| Elevation of privilege | An Operator changes a threshold, activates an AI model, deletes records or changes settings | **In place in the service layer:** `@requires` with the role of `docs/ARCHITECTURE.md` §5 on every write in `aoi/core/services.py` (Engineer; Admin for users, settings, dataset stores and deletes; Operator for Save Image…, which every role keeps, #241); hidden pages and buttons are a convenience only (REQ-USR-001; `tests/test_roles_and_audit.py` refuses a decorator that names another role than §5 and calls each write with every lower role, #181); since #197 a start signs in the role the users table holds, and Settings saves only for an Admin, audited as `settings.change` (`test_req_usr_001_saving_settings_needs_the_admin_role_and_is_audited`). Reads and inspections need no role by design: an Operator inspects boards. **Gap:** Switch User makes anyone an Admin (Spoofing row), so the check stops a role, not a person, until sign-in at release 1.0 |

## Page 2: Training and datasets

**What it does.** An Engineer imports OK and NG boards (files, or a folder with `ok/` and `ng/`), labels them and
draws defect boxes, has a second user check the labels, runs the labeller agreement check, freezes a dataset version
with its manifest, locks its validation set, trains an AI model version from it, validates it on AI Model Test and
activates it; recipes hold the ROIs and thresholds. An Admin keeps each customer's images in an encrypted dataset
store (Settings › Dataset stores; REQ-TRN-017, ADR 0010). **Assets:** the labels and boxes (a wrong label trains an
AI model that misses defects), frozen dataset versions, AI model versions and which one is active, the recipe,
validation results used as evidence, the customer's images and each store's key. **Entry points:** imported files and
folders, the Training, AI Model Test and Recipe Editor pages, Settings › Dataset stores, the recovery sheet.

| STRIDE | Threat | Status |
|---|---|---|
| Spoofing | A label check, an agreement check, a dataset change or an activation is made under another user's name | **Gap**, as page 1. A label check must come from a user other than the labeller (AOI-TRN-033, `tests/test_label_checks.py`) and the agreement check needs two labellers (REQ-TRN-016), but each is a picked name until sign-in (REQ-TRN-004 in `docs/requirements/stage1.md`), so one person who picks two names meets both rules. **Plan:** as page 1 (REQ-USR-002 to REQ-USR-005, release 1.0) |
| Tampering (poisoning) | NG boards slipped into the OK folder, labels flipped or a frozen file replaced, so the next AI model takes the defect as normal | **In place:** import, labels, boxes, checks, freezing, the split, training and activation need the Engineer role and are audited with the object and counts; each import checks a file by its content and records its SHA-256 (REQ-TRN-001, `tests/test_sample_import.py`); labels and boxes are kept with their history, who and when, and refuse UPDATE and DELETE by trigger (migration 0014, `tests/test_labels.py`); a second user checks every NG label and a seeded 10 % draw of OK labels before a freeze (REQ-TRN-004, `tests/test_label_checks.py`), and a freeze needs an agreement check that reached its targets (REQ-TRN-016, `tests/test_labeller_agreement.py`; AOI-TRN-027, `tests/test_datasets.py`); a frozen version's manifest records each file's SHA-256 and never changes, Verify Manifest lists a file changed or missing (AOI-TRN-023, `tests/test_datasets.py`), and training stops on a file whose SHA-256 is not the one frozen (AOI-TRN-045, `tests/test_train_from_version.py`); a locked validation image never trains (AOI-TRN-043, `tests/test_validation_set.py`); a new AI model version installs inactive with its AI model card, cannot be activated without one (AOI-TRN-049) and Roll Back goes back in one click (`tests/test_model_go_live.py`). This closes the 0.2.0 gap of no AI model card (REQ-TRN-011, `aoi/core/model_card.py`, `tests/test_model_card.py`). **Gap:** the go-live gate (on the locked validation set, no Critical defect missed that the live version catches, and a false call rate up by at most 1 percentage point) is not built; the S30s plan of 0.2.0 did not close it, and it is REQ-TRN-012, MUST at release 1.0. A new active AI model is a verdict-changing change and needs the customer's re-validation ("Change control", MUST), which the release note's first section says |
| Repudiation | "That AI model was not trained on those images" | **In place:** each AI model file and its registry row record its seed, every training setting, the code that trained it (a commit, or the build's version) and its dataset version, and so does the audit entry of its training (REQ-TRN-009, `aoi/core/lineage.py`, `tests/test_lineage.py`); the version's manifest names every file by SHA-256 with its labeller and checker, and the manifest's own SHA-256 is stored (REQ-TRN-005); validation runs keep their source, counts and per-image results with the UUID of the AI model that judged them (`test_runs`, migrations 0009, 0020 and 0021). This closes the 0.2.0 gap (no dataset hash, seed, code commit or settings) |
| Information disclosure | The dataset and the Golden board are the customer's boards | **In place:** a board model moved into its customer's dataset store has its images and manifests encrypted at rest under that store's key and read decrypted in memory only; a shred deletes the key, then the files (REQ-TRN-017, ADR 0010; `tests/test_dataset_stores.py`, `test_req_trn_017_store_encrypted_at_rest`, `test_req_trn_017_no_plain_file_while_training`); a board model in no store stays plain and cannot be frozen (AOI-TRN-027). Golden boards, AI models, results and `aoi.sqlite` stay plain (ADR 0010, Consequences). They stay in the workspace, except that a picture of any board loaded on Inspection, a sample or the Golden board among them, can leave through Save Image… (F9) for every role, audited as `export.image` (#241); Export AI Model and Export Manifest… are Engineer writes, audited as `export.model` and `export.csv` with the destination. **Decision 7:** whether an AI model deliverable may leave the site without the customer's written note (Legal, customer data) |
| Information disclosure | A store's key or recovery sheet is taken, and with a copy of the workspace or a backup opens a customer's images | **In place:** one random 256-bit key per store, kept only in Windows Credential Manager for this PC (`CRED_PERSIST_LOCAL_MACHINE`, so it never roams) and never in the workspace, `settings.json`, a log or an audit entry, which names the key id only (`aoi/data/credentials.py`, `create_store` in `aoi/core/services.py`; `tests/test_dataset_stores.py`, `test_req_trn_017_store_made_once_and_key_restored`; `tests/test_dataset_store_crypto.py`, `test_req_trn_017_windows_credential_manager` on the Windows runner); the recovery sheet is shown once, in a label that cannot be selected or copied, and cleared on Close (`aoi/ui/pages/settings_stores.py`; `tests/test_dataset_stores_screen.py`, `test_req_trn_017_new_store_shows_its_recovery_sheet_once`); Restore Key… saves a typed sheet only when its HMAC check value matches the store's, for an Admin, audited as `store.restore`. **Gap:** DPAPI opens the key to every process of the same Windows account, so another tool run by the station's user can read it, and plain bytes in memory can reach the page file (ADR 0010, Consequences); Print Sheet… offers every printer, a PDF printer or a networked one among them, which keeps a copy the app cannot see, and the engineer manual does not say to print on a local printer only; the install guide does not yet advise BitLocker for customer stations, as ADR 0010 decision 1 says it does (`docs/install/install.md` has no such line). **Plan:** both are lines in `docs/manual/engineer.md` and `docs/install/install.md`, open item for Jay |
| Tampering | A store's file is changed, moved, swapped, put into another customer's store or replaced by a plain file | **In place:** file format 1 is AES-256-GCM with the header, the store's UUID and the file's workspace-relative path as associated data, so a changed, moved, swapped or foreign file does not open, and a file without the header is never read as plain (AOI-TRN-025; `aoi/core/crypto.py`; `tests/test_dataset_store_crypto.py`, `test_req_trn_017_format_1_round_trip_and_refusals`; `tests/test_dataset_stores.py`, `test_req_trn_017_changed_moved_or_foreign_file_refused`); a board model never leaves its store, and a training run never mixes customers or goes beyond the uses a version allows (AOI-TRN-044, AOI-TRN-046; `test_req_trn_017_mixed_customers_refused`) |
| Repudiation | "That customer's data was never shredded", or "we never held it" | **In place:** creating a store, Restore Key…, moving a board model in and shredding are Admin writes audited as `store.create`, `store.restore`, `store.move_in` and `store.shred`, and a shred adds a row to `store_shreds`, which, like `dataset_stores` and `board_model_stores`, refuses UPDATE and DELETE by trigger (migration 0019; `tests/test_dataset_stores.py`, `test_req_trn_017_shred_ends_store_for_good`, `test_req_trn_017_interrupted_shred_resumes`). A shred deletes the key on the station it runs on only, so a station that restored the key from the sheet holds it until its own workspace shreds the store, and the written confirmation the Legal standard asks for follows the shred on every such station (ADR 0010, "As built in S38") |
| Denial of service | A lost Windows account, a reinstall or a new PC loses a store's key, and the customer's images with it | **In place:** the recovery sheet restores the key (Restore Key…; `tests/test_dataset_stores_screen.py`, `test_req_trn_017_restore_key_from_the_sheet`); the uninstaller keeps the keys in Credential Manager (`installer/aoi.iss`; `docs/install/install.md`, "Uninstall"); the backup steps keep each sheet apart from the backup (`docs/install/install.md`, "Backup and restore"). **Gap:** a lost key and a lost sheet lose the store, as a shred does (ADR 0010); there is no one-click backup with restore tested every release ("Hardening extras", SHOULD) and no requirement row for one; neither the backup nor the restore has been tried on the reference PC. **Plan:** open item for Jay |
| Denial of service | A folder of thousands of images, or one crafted image, ties up the station | **In place:** import runs on the pool with progress, time left and Cancel, and a UI-thread stall over 2 s turns a test red (`tests/test_no_freeze.py`, `test_req_set_021_training_folder_import_does_not_freeze`); since S31 an import checks each file with page 1's checks before it copies it (`imaging.checked_bytes`), never writes its source, and records its SHA-256 (REQ-TRN-001); training runs on the pool, one run at a time, on any page, with progress, the time left and Cancel after each image, step or map (REQ-TRN-008, `tests/test_training_job.py`); since 0.2.0 the label editor reads its image on the pool (`show_sample` in `aoi/ui/pages/training_labels.py`), which closes the sample-preview part of the 0.2.0 gap. **Gap:** no cap on images per import (10,000 proposed, Decision 1); training has no stall test (REQ-SET-021); the Recipe Editor still reads the Golden board on the UI thread (`RecipeEditorPage._read_golden_board`) at every header board-model change, for every role, since `MainWindow._on_board_model` tells every page, at start-up when the board model last in use opens again, and on show when the Golden board's file has changed, so a file within the checks can still hold the UI for seconds (about 2.9 s for a crafted 200 MB JPEG in `load_image`, about 10 s for the costliest TIFF, page 1); AI Model Test keeps an overlay of every image it judges, and nothing removes them (page 3). **Plan:** REQ-SET-021, open |
| Elevation of privilege | An Operator imports samples, changes a recipe or activates an AI model; an Engineer opens, moves or shreds a customer's store | **In place:** role checks in the service layer, as page 1; creating a store, Restore Key…, moving a board model in, shredding and Training's Remove of a sample need the Admin role (`tests/test_roles_and_audit.py`, `EXPECTED_ROLE`; `tests/test_logs_history.py`, `test_req_log_003_only_an_admin_removes_a_sample`); the Recipe Editor and Training pages are hidden from Operators, and Settings from all but Admins, as a convenience. **Gap:** Switch User (page 1) |

## Page 3: Files and AI models

**What it does.** Stores everything under the workspace: `aoi.sqlite`, `settings.json`, `logs/`, `images/`
(encrypted for a board model in a store), `models/<board>/<board>_<version>.pt` with its `_golden.png` and its AI model
card (`.card.md`, `.card.json`), `datasets/<name>/manifest.json`, `results/` and `exports/`; the demo workspace sits
beside it, and each store's key in Credential Manager. Paths are stored relative to the workspace and resolved by
`aoi/data/paths.py`; every file but the append-only log is written through `aoi/data/atomic.py`; the schema changes
only by numbered migration (22 at 0.3.0), each after a copy of the database (REQ-SET-016). **Assets:** the integrity of
AI model files (they decide verdicts), the database, the log as evidence, the customer's images. **Entry points:** the
files themselves, AI model files from outside, the `AOI_WORKSPACE` and `AOI_DEMO_BUNDLE` environment variables,
`settings.json`, the demo's `demo.json` marker.

| STRIDE | Threat | Status |
|---|---|---|
| Spoofing | A different `.pt` is dropped in place of the active AI model, so the station scores with an AI model nobody approved | **Gap, in part.** Loading refuses code (next row) and, since #168, a file whose metadata UUID is not the one its `models` row names (`AOI-TRN-001`; `tests/test_model_files.py`, `test_req_trn_014_case_variant_names_and_another_models_file_are_refused`), such as another AI model file of this app written over it; a crafted file that copies the UUID still loads. Since 0.2.0 each record stores the SHA-256 of the Golden board the engine read (REQ-CMP-003, migration 0008), so a swapped Golden board shows on Compare afterwards, but nothing checks it before a board is judged. The standard's "Untrusted inputs" rule (MUST) takes AI model files only from our signed packages, and nothing is signed yet (page 4). **Decision 2 (proposed):** store the SHA-256 of the AI model file and Golden board in the `models` row at training and check it at load, refusing a mismatch with a new AOI-TRN code (`AOI-TRN-001` means a file that needs code to load); the same hash in the SBOM and the AI model card |
| Tampering | An AI model file that runs code when loaded (PyTorch files are pickles) | **In place:** `torch.load(path, weights_only=True)` on PyTorch 2.6 or later (2.14.1 pinned), metadata stored as tensors and plain values only, and a file that needs code is refused with `AOI-TRN-001` (`aoi/core/anomaly.py`, REQ-TRN-014; `tests/test_model_files.py`, `test_req_trn_014_crafted_pickle_is_refused`); a syntax-tree scan turns CI red on a torch.load without a literal `weights_only=True` and on the pickle, shelve, joblib, dill, TorchScript and pickle-allowing NumPy loaders it lists, anywhere in `aoi/`, `tools/` or `main.py`, resolving each name through every import alias and name binding in the module, and checking every loader a name may stand for (`tests/test_security_rules.py`, `test_req_trn_014_no_unsafe_torch_load_in_source`, #168); a loader reached through importlib, a container, a loop variable, a call result or a module given as an argument is not caught, and code review covers it; a zip entry flagged as a folder, which torch would leave unread, is refused too (#168). ## Page 4: Installer and build

**What it does.** CI (`.github/workflows/build.yml`) builds a PyInstaller one-folder app with the demo bundle, starts
it, runs its `--self-test` on a synthetic board, and wraps it in an Inno Setup installer that it installs, self-tests
and uninstalls on the runner, on every push to main, on pull requests that change the build and on every `v*` tag
(ADR 0007). The installer is unsigned and for internal tests only: it installs for every user into
`C:\Program Files\AOI PoC Inspector` with admin rights, the app runs as a standard user, and the uninstaller keeps
the workspace, the demo workspace, `settings.json` and the store keys. A release (a signed installer from a tagged
commit after two approvals) does not exist yet. **Assets:** the integrity of what testers and, later, customers run,
the build chain's credentials, the station's Windows configuration, the demo bundle. **Entry points:** the dependency
set and its locks, the CI pipeline and the actions it uses, Inno Setup from Chocolatey, the folder and installer
artifacts, the demo bundle, the update path.
